# Portable density recipe

The web/coordinate build is offline from packaged inputs. Full density regeneration additionally needs the hash-checked primary map/structure-factor cache; raw maps remain outside the web repository. Archived source manifests and small metadata/header snapshots are packaged under build/inputs/density_sources and density_metadata. The original as-run scientific method is retained, with explicit paths replacing Windows-profile constants.

Use the pinned `build/requirements-density.txt` environment (including Matplotlib 3.11.2) for preparation/native CIFs, and a separate PyMOL 3.1 environment for meshes. No dependency upgrade is required. On this workstation use the shared scientific Python and the explicit ps1_pymol exception documented in the project instructions. --work-dir must be outside the repository. Choose a fresh work directory for a new derivation; earlier results are not deleted.

1. `python tools/density/fetch_sources.py --map-cache CACHE --work-dir WORK --ids 7DKZ 9KZ9` retrieves missing exact sources, or supply an existing cache. Existing mismatches and partial files cause a stop, not an overwrite. Optional CACHE/cache_index.json maps portable relative source names to existing local files, avoiding duplicate multi-GB maps or junctions. Cache aliases are local-only and are not part of the public package.
2. `python tools/density/prepare.py --map-cache CACHE --work-dir WORK --ids 7DKZ 9KZ9 1JB0` creates native-coordinate sections, atom samples and crops. The frame gate binds the source to the independent archived/current snapshot check in the review configuration; it does not claim a new online/model-quality test.
3. `python tools/density/native_cif.py --work-dir WORK --ids 7DKZ 9KZ9` creates full-precision figure-only CIFs.
4. In the PyMOL environment: `python tools/density/render_meshes.py --work-dir WORK --output-dir MESH_OUTPUT --ids 7DKZ 9KZ9`. Source PML must have the case-correct MG sphere selection. Output reports verify Mg visibility, disabled normalization, exact before/after PyMOL coordinates and the documented carve/buffer.
5. For all entries, omit --ids. Keep 1JB0 explicitly unavailable; the recipe never invents missing maps/waters/atoms. For 9AU4, prepare the author-level inputs first, then `python tools/density/contour_sections.py --map-cache CACHE --work-dir WORK --ids 9AU4`, and separately use `render_meshes.py --work-dir WORK --output-dir ALTERNATIVE_MESH_OUTPUT --ids 9AU4 --contour-mode mean-plus-3sd`. The alternative is explicitly restricted to this reviewed display case.

EM values/sampling are unchanged. Crystal weighted maps use full-cell normalization, FFT sample rate 3 and the declared contour levels; crops are not renormalized. Sections use 0.14 Å trilinear raster sampling and projected ±1 Å model slabs. Meshes use 2 Å carve / 4 Å buffer with PyMOL normalization disabled. The recipe is a visualization derivation, not refinement, an omit map, a support score or a hydrogen-bond assignment. See docs/DENSITY_VISUALIZATION_PILOT.md and docs/SCIENTIFIC_REVIEW.md.

The recipe's image outputs may differ in bytes with plotting/renderer/platform versions; source/coordinate/frame/parameter checks and packaged image hashes provide the relevant evidence. It does not claim arbitrary cross-platform pixel identity. Fresh preparation requires sufficient RAM for the full unnormalized primary map.
